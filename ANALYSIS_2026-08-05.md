## 2. Оценка текущего состояния

### 2.1. Что хорошо

- Шаблоны разделены на partial'ы (HTMX-фрагменты) — аккуратная структура.
- Единый паттерн обработки ошибок API: `try/except + logger.error + unavailable_services`.
- Джентльменский набор: Dockerfile + docker-compose + Makefile + healthcheck.
- Типизация в маршрутах (`dict[str, Any]`), докстринги в русском языке — читабельно.
- Фильтры шаблонов (`datetime`, `human_size`, `time_ago`) вынесены в фабрику приложения — переиспользуемы.

### 2.2. Найденные проблемы

1. **`logs.html:141` — URL без обрезки.** `<td class="... truncate" title="{{ r.url }}">` — заголовок в tooltip есть, но сама ячейка рендерит полный URL (truncate работает, но без `max-w` у родителя может съедать ширину колонки).
2. **`dashboard.py:98-103` — N+1 не критичен, но нагрузка двойная:** `get_summary` вызывается на каждый рендер главной страницы; при недоступности LogSpy счётчики тихо становятся нулями (баннер есть — ок).
3. **`hosts.py:28` `_sort_hosts`, `netcerber.py:31` `_sort_devices`, `printers.py:57` `_sort_printers` — дублирование кода сортировки** (3 одинаковые функции с картами `SORT_FIELDS`).
4. **`users.py` — 2 вызова `get_data` подряд** (основная выборка + подсчёт `blocked`). Если LogSpy медленный, страница пользователя тормозит; можно параллелить через `threads` или кэшировать.
5. **`config.py` — конфигурация жёстко зашита в классе** (IP:8101–8104, `SECRET_KEY` placeholder). Не читается из `.env` — рекомендуется вынести в переменные окружения.
6. **`logs.py:63` — фильтр `user` применяется на клиенте после выборки:** `records = [r for r in raw_records if r.get("user") and r["user"] != "-"]` — режет страницу на клиенте, пагинация может «плыть» (кол-во записей на странице не равно `limit`).
7. **`user_detail.html` — `stats` из `get_data` не используется** (переменная `stats` в `users.py:126` не передаётся в шаблон).
8. **`netcerber.py:369` строк — самый большой маршрут**, содержит HTML-фрагменты в Python? (проверить: если да — вынести в partial).
9. **`app/__init__.py:58-61` — `log_unknown_requests` — пустой `pass`-хендлер**, мёртвый код.
10. **`static/css/` пустая директория** — упоминается в README, но не используется (Tailwind с CDN).

## 3. Предложения по рефакторингу (приоритизированные)

### P1 — Безопасность / инфраструктура
- [ ] **1. Конфигурация через окружение.** В `config.py` читать `os.getenv(...)` с дефолтами; пример в `.env.example`; `SECRET_KEY` — только из env, с предупреждением при дефолтном.
- [ ] **2. Убрать `DEBUG = True` из дефолтной конфигурации** (опасно для продакшена); `DEBUG` из env.

### P2 — Производительность / корректность
- [ ] **3. Пагинация логов:** перенести фильтр `user != "-"` на сторону API (параметр `user` уже передаётся — проверить, что LogSpy фильтрует сам, тогда убрать клиентский фильтр) или считать пагинацию по отфильтрованному количеству.
- [ ] **4. Параллельные запросы в `users.py`:** оба вызова `get_data` выполнять через `concurrent.futures.ThreadPoolExecutor` (не критично, но ускорит страницу при медленном LogSpy).
- [ ] **5. Кэширование сводки dashboard** (например, `cachetools.TTLCache` на 60 с) — главная страница дёргает 3 сервиса + summary каждый раз.

### P3 — Код / дублирование
- [ ] **6. Общая функция сортировки** `sort_items(items, field_map, sort_by, order)` вместо трёх копий в `hosts.py`, `printers.py`, `netcerber.py` (вынести в `app/utils.py` или в общий миксин).
- [ ] **7. Вынести `_get_*_client()` в один модуль** (или во `flask.current_app.extensions`) — сейчас 4 blueprint'а дублируют одинаковые фабрики.
- [ ] **8. Удалить мёртвый код:** пустой `log_unknown_requests`, неиспользуемую `stats` в `users.py`.
- [ ] **9. Разобрать `netcerber.py`** (369 строк): проверить, нет ли инлайн-HTML в Python; вынести JS/шаблоны в partial.
- [ ] **10. Объединить фильтры шаблонов** в `app/templating.py` (registry) — сейчас всё в `create_app`, файл растёт.

### P4 — UX / мелочи
- [ ] **11. `logs.html`: добавить `max-w` для колонки URL** (ячейка `truncate` без ограничения ширины не работает корректно).
- [ ] **12. Пустую `static/css/` либо наполнить (main.css для сборки Tailwind), либо убрать из README.**

## 4. Тесты / проверка (рекомендации)

- Запустить локально: `make run` (или тестовый инстанс на 5001), проверить `/`, `/users/...`, `/logs/`, `/hosts/`.
- Проверить баннер недоступности: временно указать неверный URL сервиса.
- После рефакторинга прогнать все страницы через `curl -o /dev/null -w "%{http_code}"`.

## 5. Итог

Проект в хорошем состоянии: последние изменения закрыли главные UX-ошибки (завышенные метрики,
нечитаемые размеры, «тихие» сбои сервисов, неинформативный статус OFFLINE). Рекомендуемые
действия — P1 (безопасность) и P2 (пагинация, кэширование) в первую очередь; P3-P4 — по мере
необходимости. Общий объём кода ~4 300 строк — поддерживаемый, без архитектурных долгов.
