# NetView

**NetView** — это веб-панель мониторинга IT-инфраструктуры, построенная на Flask. Предоставляет единый интерфейс для контроля состояния принтеров, хостов, пользователей Active Directory, логов Squid и управления стоп-листом.

## Интерфейс

- **Dashboard** — агрегированная статистика по принтерам, хостам, AD и логам
- **Принтеры** — список устройств с уровнем тонера, сортировка через HTMX
- **Хосты** — таблица с CPU/RAM/Disk, статусом ONLINE/OFFLINE; для выключенных хостов — баннер с датой последнего контакта и «устаревшие» (серые) метрики
- **Пользователи** — просмотр AD-пользователей с активностью в Squid (включая заблокированные запросы), авторитетные счётчики запросов и блокировок
- **Логи Squid** — поиск и фильтрация по user/domain/status, сортировка, человекочитаемые размеры (KB/MB/GB)
- **NetCerber** — мониторинг устройств локальной сети, авторизация, журнал сканирований, удаление устаревших записей из модалки устройства, чип «Расхождение данных» (роутерный вендор при разрешённом hostname — признак переезда IP на другой хост), группировка дублей по IP с историей и точечной чисткой, блокировка несанкционированных устройств на шлюзе OPNsense/TING (алиас MAC + правило брандмауэра), ограничение скорости каналом шейпера TING из карточки устройства
- **Стоп-лист** — добавление/удаление стоп-слов для блокировки
- **Настройки** — порог тонера, интервал проверки принтеров

При недоступности какого-либо сервиса на страницах отображается баннер «Сервис недоступен» — вместо «тихих нулей».

### Используемые технологии

- Flask 3.x, Jinja2, TailwindCSS 3.4 (прекомпилированный CSS: `make css`)
- HTMX 2.x — асинхронная подгрузка и сортировка без JS
- FontAwesome 6 (локальные статики)

### Блокировка устройств на шлюзе (OPNsense / TING)

Активное реагирование — правило брандмауэра прямо на **шлюзе** (единственная точка, где сходится весь трафик сети). Шлюз режет **весь** трафик источника по **MAC**. Схема — один общий алиас + одно правило:

- **Алиас** `netview_block_mac` (тип `mac`) — список заблокированных MAC. Блок/разблок = добавить/убрать MAC из содержимого алиаса (`POST /api/firewall/alias/setItem/<uuid>`; на TING элементы пишутся через **перевод строки**, а `setItem` требует `alias[name]` в теле) с последующей перегрузкой alias-таблиц (`POST /api/firewall/alias/reconfigure`).
- **Правило** `description=netview-block` (`POST /api/firewall/filter/addRule`, `source_net=<алиас>`, `action=block`, `interface=lan`, `direction=in`, `quick=1`) создаётся один раз и ставится в **начало** списка: на TING нет `moveRuleBefore`, позиция задаётся целым полем `sequence` (`setRule`) — если правило не первое, остальные сдвигаются на +1, а нашему ставится `1`. Иначе стоящее выше «разрешить всё на LAN» перекроет блокировку. Структурные изменения применяются через `apply`.
- **Вручную подчищать содержимое алиаса не нужно**: при блокировке отсутствующие алиас/правило доздаются автоматически; остатки старой схемы (`netview_mac_*` алиасы и правила `netview-block-<MACHEX>`) мигрируются в общий алиас и удаляются.
- **Разблокировка/статус**: `getRule` + `searchItem` — правило есть и активно ⇒ MAC из алиаса считается заблокированным.
- **Защита**: `OPNSENSE_PROTECTED_MACS` — блокировка таких MAC отклоняется.

Требует модуль **os-firewall** (и поддержку MAC-алиасов на интерфейсе LAN) на шлюзе и пару API-ключей (System → Access → Users → API keys).

### Ограничение скорости (Traffic Shaper / TING)

Отдельная от блокировки функция: из карточки устройства выбирается «канал» (pipe шейпера напр. 5Mbit, 10Mbit…) и **применяется** на шлюзе, или **снимается**. Работает через модуль **os-trafficshaper**: записи — одна точка привязки правила шейпера к устройству, переживающие смену IP, отсутствуют; как и правила оператора, ограничение матчит `destination=IP → target=канал` на интерфейсе **lan**:

- **Каналы и текущее правило** читаются `GET /api/trafficshaper/settings/get`; список каналов строится из `pipes` (канал = имя + полоса + единицы), а состояние устройства — поиск правила с `description=netview-shape-<MACHEX>` (без `:`: описание не выдерживает двоеточия).
- **Применить** = создать/обновить правило `POST /api/trafficshaper/settings/addrule|setrule/<uuid>` с JSON-телом `{"rule": {...}}` (form-передача на TING падает с `Undefined index: uuid`; пустые `src_port`/`dst_port`/`source_not`/`destination_not` не передаются вовсе). Поля: `interface=lan`, `proto=ip`, `direction=""` (оба направления), `source=any`, `destination=<IP устройства>`, `target=<uuid канала>`, `sequence=90` (ниже персональных правил оператора 1..10). Затем `POST /api/trafficshaper/service/reconfigure`.
- **Снять** = удалить наше правило `POST /api/trafficshaper/settings/delrule/<uuid>` + `reconfigure`.
- **Нюанс**: правило матчит именно **IP**, поэтому применение требует у устройства IP-адрес; смена IP сводит ограничение на нет (как у правил оператора).
- Включается флагом `OPNSENSE_SHAPER_ENABLED` независимо от блокировки; креды те же.

Требует модуль **os-trafficshaper** на шлюзе; управление «каналами» (создание/полоса) выполняется в веб-морде TING (Firewall → Shaper), NetView только назначает существующий канал устройству.

Пример:

```bash
cp .env.example .env
# отредактируйте .env: SECRET_KEY, AUTH_USERS, DHCP_POOL, адреса сервисов
```

`.env` исключён из git и Docker-образа; в репозитории лежит только шаблон `.env.example`.

### Запуск в Docker

```bash
cp .env.example .env   # заполнить реальные значения
make build && make up
```

Compose читает переменные из `.env` (`env_file`). Внутри контейнера `localhost` — сам контейнер, поэтому сервисы на хост-машине доступны по `host.docker.internal` (в compose добавлен `extra_hosts: host-gateway`).

## Безопасность

- Все страницы закрыты аутентификацией (flask-login); вход — по учётным записям из `AUTH_USERS`.
- Все изменяющие запросы (POST/PUT) защищены от CSRF (flask-wtf); HTMX-запросы автоматически подписываются токеном через `X-CSRFToken`.

## Git

Репозиторий инициализирован; чувствительные файлы (`.env`, виртуальное окружение, кэш, БД, логи, ключи/сертификаты) исключены через `.gitignore`. Для смены параметров сервисов рекомендуется вынести `app/config.py` на переменные окружения.
