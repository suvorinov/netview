## 2. Архитектура

```
Браузер (HTMX + Tailwind)
   │
   ▼
Flask WSGI ──► Blueprints (routes/)      ← только оркестрация и HTML
   │                    │
   │                    ▼
   │              api/ (BaseApiClient + 4 клиента)   ← HTTP к микросервисам
   │                    │
   ▼                    ▼
auth.py / utils.py    Printer :8101 · Host :8102 · LogSpy :8103 · NetCerber :8104
```

**Слои разделены правильно:**

- `app/__init__.py` — фабрика `create_app`, фильтры шаблонов, хуки `before/after_request`. Классический application factory — тесты это уже используют.
- `app/api/base.py` — единая точка HTTP: таймаут, `raise_for_status()`, keep-alive через `requests.Session` (base.py:34).
- `routes/` — тонкие контроллеры: получить данные → отрендерить шаблон. Бизнес-логика (критичные принтеры, признаки подозрительности устройств) вынесена в приватные функции модулей.
- `utils.py` — переиспользуемые чистые функции (`human_size`, `sort_items`, `is_router_vendor`) без зависимости от Flask — легко тестируются.
- `config.py` — всё через env, случайный `SECRET_KEY` как fallback с явным предупреждением в лог.

**Сильные архитектурные решения:**

1. **Параллельные запросы к сервисам** на Dashboard и Настройках (ThreadPoolExecutor): страница не ждёт недоступный сервис по очереди до 20 с (dashboard.py:142).
2. **Graceful degradation**: баннер «Сервис недоступен» вместо тихих нулей; при этом парсинг ответа вынесен из `try` — баг формы данных не маскируется под «сервис упал» (logs.py:66, dashboard.py:186). Это зрелое различение двух классов ошибок.
3. **TTL-кэш счётчиков чипов NetCerber** (30 с, в `app.extensions`, у каждого инстанса свой) — экономит полную выборку при каждом действии со списком (netcerber.py:230).
4. **CSRF для HTMX** решён элегантно: токен из `<meta>` подставляется хуком `htmx:configRequest` во все запросы (base.html:53).

### 🔴 P1 — стоит сделать в первую очередь

> **Статус (обновлено 2026-08-24): все четыре пункта выполнены** —

#### P1.1. ✅ Дублирование фабрик клиентов: было 17 копий в routes/
`_get_logspy_client()` определена в 6 модулях, `_get_printer_client()` — в 2, и т.д. Всего **17 одинаковых функций-фабрик** (dashboard.py:31–41, settings.py:24–42, logs.py:19, users.py:29, stoplist.py:19, netcerber.py:81–86).

Две проблемы:
- **DRY**: изменение конструктора клиента = правки в 6 местах.
- **Потерянный keep-alive**: клиент с новой `Session` создаётся *на каждый запрос*, поэтому TCP-соединения не переиспользуются между запросами, а комментарий в base.py:30 про «10 рукопожатий» верен только внутри одного запроса.

**Решение** — создать клиентов один раз на экземпляр приложения:

```python
# app/api/factories.py
from flask import current_app
from app.api.host_client import HostMonitorClient
# ...

def get_host_client() -> HostMonitorClient:
    """Клиент Host Monitor, лениво создаваемый и кэшируемый на app."""
    clients = current_app.extensions.setdefault("api_clients", {})
    if "host" not in clients:
        clients["host"] = HostMonitorClient(current_app.config["HOST_API_URL"])
    return clients["host"]
```

Сессия живёт между запросами → реальный keep-alive, минус ~200 строк дублей. Пул urllib3 потокобезопасен — параллельные задачи Dashboard продолжат работать.

#### P1.2. ✅ Нет серверной валидации threshold/interval — исправлено (диапазон 0–100% и 10–86400 сек)
settings.py:155 и 181: `request.form.get("threshold", 20, type=int)` примет `-5` или `99999` и отправит их в API. При этом планировщик NetCerber валидируется образцово (netcerber.py:636: `0 < hours <= 168`). Нужна такая же проверка:

```python
threshold = request.form.get("threshold", 20, type=int)
if not 0 <= threshold <= 100:
    return render_template("partials/_settings_result.html",
                           success=False, message="Порог: 0–100%")
```
Аналогично для интервала (например, 10…86400 сек).

#### P1.3. ✅ Фильтр пользователя ломается при пустом AD_DOMAIN — исправлено
logs.py:29–30: если пользователь ввёл имя без `@`, домен дописывается всегда — даже когда `AD_DOMAIN=""`, получается фильтр `"user@"`, который ничего не найдёт. Обернуть в условие:

```python
if user_filter and "@" not in user_filter and current_app.config["AD_DOMAIN"]:
    user_filter = f"{user_filter}@{current_app.config['AD_DOMAIN']}"
```

#### P1.4. ✅ Незакоммиченные изменения и битая ссылка в README — зафиксировано
В рабочем дереве ~19 изменённых файлов и удалённый (но не закоммиченный) `ANALYSIS_2026-08-19.md`, на который ссылается README.md:70. Стоит зафиксировать текущее состояние коммитом и почистить упоминание несуществующего файла.

#### P2.2. ✅ Session fixation — исправлено (`session.clear()` перед `login_user`)
`login_user()` в auth.py:112 не очищает старую сессию. Перед входом рекомендуется:

```python
session.clear()
login_user(User(username))
```

Риск для внутренней панели низкий, но исправление — одна строка.

#### P2.3. ✅ Утечка деталей ошибок в JSON — исправлено (5 эндпоинтов возвращают «LogSpy недоступен»)
stoplist.py:57, logs.py:123/138, users.py:272 возвращают `jsonify({"error": str(e)})` — наружу уходит URL внутреннего сервиса и диагностика requests. В лог пишется всё (это хорошо), а клиенту лучше generic-сообщение: `{"error": "LogSpy недоступен"}`.

#### P2.4. ✅ HTMX-фрагменты молчат при падении сервиса — исправлено (хосты/принтеры/статистика/NetCerber)
`htmx_hosts_list` (hosts.py:79), `htmx_printers_list` (printers.py:80), список логов — при `RequestException` рендерят пустой список без баннера. После первой загрузки пользователь видит «пусто», а не «сервис недоступен». Передавать `unavailable_services` во фрагменты (как это уже сделано в `_netcerber_device_list.html` через oob-блоки).

#### P2.5. ✅ Tailwind Play CDN в проде — исправлено (скомпилированный app.css 27 KB вместо ~400 KB JS-рантайма)
`vendor/tailwind.js` — это runtime-JIT сборка Tailwind (base.html:19): CSS генерируется в браузере при каждой загрузке страницы (~300+ KB JS + компиляция). Для внутренней панели приемлемо, но правильнее прекомпилировать статику Tailwind CLI на этапе сборки Docker — быстрее и снимает будущие проблемы с CSP (`unsafe-inline`).

#### P2.6. ✅ Logout по GET — исправлено (POST-форма с CSRF)
Ссылка «Выход» — GET (auth.py:124): внешний `<img src="/logout">` на любой странице разлогинит пользователя. Не критично, но POST-формой — гигиеничнее.

## 5. Качество кода

**Хвалю (и это не комплимент ради комплимента):**

- Docstrings в Google-style почти на каждой функции и классе, включая `Attributes:`/`Args:`/`Returns:` — редкость для внутренних инструментов.
- Комментарии объясняют *почему*, а не *что*: история про naive/aware datetime, ронявшую страницу (app/\_\_init\_\_.py:74), про `bool("false") == True` (netcerber.py:59), про лимит 500 у LogSpy (logspy_client.py:44). Такой код приятно сопровождать.
- Типизация: современный синтаксис `dict[str, Any]`, `X | None`, union-паттерн `isinstance(first, int | float)` — py312 target используется по полной.
- Обработка ошибок последовательна: `RequestException` = «сервис недоступен» → дефолт + баннер; всё остальное = честная ошибка.
- `_verify_password` с веткой pbkdf2 и `compare_digest` — правильный подход к двойному формату хранения.
- Функция `sort_items` с NULLS LAST-семантикой — аккуратное обобщение для трёх разных таблиц.

**Мелкие придирки:**
- `netcerber.py` разросся до 738 строк и 20 маршрутов — кандидат на сплит (`devices.py` / `scans.py` / `scheduler.py` blueprint'ы), но пока читаемо за счёт секционных комментариев.
- В `dashboard.index` после параллельного блока идёт ~60 строк распаковки результатов — просится dataclass `DashboardData` и отдельные сборщики (`_collect_printer_block(results)`, ...). Чисто косметика.

104 теста: auth (12), routes (42), utils (31), clients (1). Есть свой мини-хелпер логина с CSRF-токеном (conftest.py:26) — тесты проходят полный цикл аутентификации, а не обходят её моками. Это дорогого стоит.

- нет smoke-теста «все страницы открываются с замоканными клиентами» — он поймал бы забытый импорт при рефакторинге.

## 7. Инфраструктура

- **Dockerfile**: slim-образ, точечное копирование `app/` и `run.py`, без слоёв с секретами — хорошо. Healthcheck бьёт в `/` и проходит редирект на `/login` — работает, но завязан на поведение auth; явный `/health`-эндпоинт надёжнее.

- **requirements.txt** пины точные; для воспроизводимости можно добавить hash-пины (`pip-compile`), но для внутреннего контура не обязательно.
